# AI 使用说明

这个项目在开发过程中用了 AI 工具。写这份说明，一是用了就该说清楚，二是方便后来的人判断哪些地方值得再核一遍。

## 用了什么

| 工具 | 用在哪 |
| --- | --- |
| 大语言模型（对话式编程助手） | 页面与交互代码初版、云服务集成、文案初稿、文档结构 |
| 文生图模型 | 5 张配图 |
| 大模型 API（站内） | 茶博士问答。这是产品功能，不是开发工具 |

## 开发辅助

| 环节 | AI 做了什么 | 团队做了什么 |
| --- | --- | --- |
| 选题与定位 | 没参与 | 基于家乡的茶与自己的判断定下来 |
| 痛点分析 | 把团队口述的观察整理成文字 | 提出三个方向，逐条确认 |
| 内容整理 | 按给定方向检索、梳理品类、工艺、历史 | 逐条核对公开文献 |
| 前端代码 | 生成 HTML、CSS 与交互逻辑初版 | 提需求和技术约束，逐页验收、修问题 |
| 云服务集成 | 生成数据库访问、认证、模型调用的集成代码 | 设计表结构与权限模型，AI 按设计实现 |
| 文案 | 生成各模块说明的初稿 | 逐段改写定稿，关键史实自己查 |
| 文档 | 帮忙搭结构 | 定稿 |

### 它错过的三次

我们没统计过用了多少次 AI，倒是记得它错在哪三次。

**千两茶的创制年份。** 初稿写「清·道光年间」。查了三个来源才确认是嘉庆到道光（1796—1820），而且史料里有「道光百两，同治千两」的说法——百两茶先出，千两茶在后。已改。

**非遗名录。** 初稿说安化黑茶文化系统「入选全球重要农业文化遗产」。实际是千两茶制作技艺、茯砖茶制作技艺于 2022 年作为「中国传统制茶技艺及其相关习俗」的组成部分，进入联合国教科文组织人类非物质文化遗产代表作名录。两者不是一回事。已改。

**权限策略。** 它生成的数据表策略把写操作同时授权给已登录和未登录两类角色，条件写作 `owner_id = auth.uid()`。上线后真机一测，匿名访客真的写进去了——平台给未登录请求的身份是字符串 `anon`，不是空值，条件变成 `'anon' = 'anon'`，直接放行。收窄到 `authenticated`、复测通过之后才上线。细节在[设计说明](设计说明.md#四数据与权限)。

### 没让 AI 参与的

- 数据库表结构与权限策略设计
- 功能取舍与优先级
- 项目定位与创新点的提炼
- 验收用例设计与执行
- 用户数据的产生与处理

## 内置问答

茶博士的系统提示词里有一份按板块整理的知识库和六条回答准则（不确定要说不知道、不做健康功效宣称、不推荐品牌价格、控制长度等）。输出用纯文本渲染，对话不写库、不留存、不用于训练。这块的设计考虑在[设计说明](设计说明.md#五ai-的边界)。

约束不能保证它一定答对，但至少能让「不知道」被看见。

## 三条原则

1. **披露。** 用了哪些工具、用在哪一环，都写在这里。
2. **核实。** AI 生成的内容，包括文字、代码、图片、史实，都经团队看过、改过才用。
3. **决定权在人。** 选题、功能、数据模型、权限设计和验收标准由团队定，AI 不参与决策。
